# 01 — سند نیازمندی محصول (PRD)

> نقش نویسنده: **مدیر محصول**. این سند «چه و چرا» را تعریف می‌کند؛ «چگونه» در `02-ARCHITECTURE.md`.

## ۱. چشم‌انداز

> «هیچ فریلنسر یا آژانسی دیگر قیمت را حدس نزند.»

ابزاری که در کم‌تر از ۳ دقیقه، با چند ورودی ساده، یک **قیمت قابل‌دفاع** + **نمودار** + **پروپوزال سه‌سطحی** تولید می‌کند؛ کاملاً فارسی، آفلاین‌کار (PWA)، و قابل‌جاسازی در سایت کاربر.

## ۲. کاربران هدف (Personas)

| پرسونا | درد | چه می‌خواهد |
|:---|:---|:---|
| 🧑‍💻 فریلنسر تازه‌کار | نمی‌داند ساعتش چند است؛ زیر قیمت می‌دهد | عددِ کفِ مطمئن (MAR) و قیمت پروژه |
| 🏢 آژانس بوتیک | قیمت‌گذاری ناهماهنگ بین اعضای تیم | Blended Rate و خروجی استاندارد |
| 🔍 متخصص سئو | مشتری «هزینه» می‌بیند نه «سرمایه‌گذاری» | روایت ROI برای مذاکره |
| 🧾 مدیر فروش آژانس | پروپوزال سریع و حرفه‌ای | خروجی PDF سه‌سطحی |

## ۳. Jobs To Be Done

- وقتی پروژه‌ی جدیدی می‌آید، می‌خواهم **کف نرخم** را بدانم تا ضرر نکنم.
- وقتی پروژه پیچیده است، می‌خواهم **پیچیدگی و ریسک** را عددی کنم تا قیمت منصفانه شود.
- وقتی سئو می‌فروشم، می‌خواهم **ROI مشتری** را نشان دهم تا «گران» به نظر نرسم.
- وقتی تیمم بزرگ می‌شود، می‌خواهم **سربار غیرمستقیم** را در نرخ لحاظ کنم.
- می‌خواهم نتیجه را **ذخیره، چاپ و به اشتراک** بگذارم.

## ۴. دامنه‌ی نسخه‌ی اول (MVP) — هر چهار ماژول

### ماژول ۱ — موتور هزینه و MAR
ورودی: هزینه‌های مستقیم/سربار/هدف سود، هفته‌ها، ساعت هفتگی، نرخ بهره‌وری.
خروجی: `H_billable`، `C_total`، `MAR`، `Overhead Ratio` با محک رنگی. نمودار: ترکیب هزینه (Doughnut) + جایگاه MAR.

### ماژول ۲ — قیمت‌گذاری وب/وردپرس
ورودی: انتخاب از Cheat Sheet یا ساعت دستی، نرخ (MAR یا بازار)، سطح `CM`، فاکتورهای `RB` (چک‌باکس جمع‌شونده)، معماری Builder، گزینه‌های افزودنی (نگهداری، CWV، چندزبانه).
خروجی: `P_base → P_adjusted`، نمودار **Waterfall** سهم هر ضریب، و **سه سطح Essential/Pro/Enterprise** (Pro هایلایت).

### ماژول ۳ — سئو و ROI
زیربخش‌ها: (الف) برآورد Audit از روی اجزا، (ب) Retainer ماهانه، (ج) Performance Hybrid با هشدار ایمنی، (د) محاسبه‌گر ROI مشتری با روایت آماده.
خروجی: اعداد + نمودار ROI (مقایسه‌ی ارزش ماهانه با Retainer) + جمله‌ی مذاکره.

### ماژول ۴ — مقیاس‌پذیری آژانس
ورودی: نیروی مستقیم/غیرمستقیم، ردیف‌های نقش (نقش/ساعت/نرخ)، قیمت نهایی و هزینه‌ی واقعی.
خروجی: `ASF`، `Rate_agency`، `Blended Rate`، `Margin%` با محک. نمودار: سهم نقش‌ها (Donut) + جایگاه Margin.

### قابلیت‌های فرابخشی (Cross-cutting)
- **InfoTooltip («!»)** روی هر فیلد، با متن فارسی از `content/fa`.
- **تور آموزشی driver.js** برای هر ماژول + یک تور «خوش‌آمد» اولیه.
- **PWA**: نصب‌شدنی، آفلاین، آیکن/اسپلش، آپدیت خودکار.
- **ذخیره‌ی محلی**: آخرین ورودی‌ها و «سناریوهای ذخیره‌شده» در localStorage.
- **خروجی**: چاپ/PDF پروپوزال + دانلود تصویر نمودار (PNG).
- **تم روشن/تیره** + کاملاً RTL فارسی، ارقام فارسی.

## ۵. خارج از دامنه‌ی MVP (Non-Goals)
- بک‌اند، لاگین، چندکاربره، پایگاه‌داده‌ی ابری.
- دستیار هوش مصنوعی (فاز آینده — معماری باید جا برایش بگذارد ولی ساخته نشود).
- چند ارز/چندزبانه‌ی کامل UI (ساختار i18n آماده، ولی فقط فارسی عرضه می‌شود).
- لینک اشتراک سروری (فعلاً فقط فایل/چاپ).

## ۶. معیارهای موفقیت (Success Metrics)
- محاسبه‌ی یک قیمت کامل در **< ۳ دقیقه** برای کاربر تازه‌وارد.
- صحت ۱۰۰٪ خروجی نسبت به Test Vectorهای مرجع.
- Lighthouse: Perf ≥ 90، A11y ≥ 95، PWA installable.
- صفر خطای راست‌چین/شکستگی در موبایل ۳۶۰px.

## ۷. ریسک‌ها و کاهش آن‌ها
| ریسک | کاهش |
|:---|:---|
| خطای محاسباتی | موتور خالص + Test Vector + پوشش ۱۰۰٪ |
| سردرگمی کاربر با اصطلاحات | tooltip اجباری + تور driver.js |
| شکست RTL در کامپوننت‌های آماده | قاعده‌ی logical properties + تست بصری موبایل |
| حجم باندل زیاد (chart/PWA) | code-split per-feature + lazy chart |
| اختلاف ارقام فارسی/انگلیسی | `parsePersianNumber` در ورودی، `toPersianDigits` در خروجی |

## ۸. جریان کاربر (User Flow سطح‌بالا)
```
ورود → (تور خوش‌آمد) → انتخاب ماژول از داشبورد
   → پر کردن فرم (با tooltip و اعتبارسنجی زنده)
   → دیدن نتیجه + نمودار به‌صورت زنده
   → ذخیره‌ی سناریو / خروجی PDF/PNG
   → (اختیاری) رفتن به ماژول بعد؛ خروجی MAR به‌عنوان نرخ ماژول ۲ تزریق می‌شود
```
نکته‌ی زنجیره‌ای: خروجی **MAR** ماژول ۱ باید به‌عنوان نرخ پیش‌فرض در ماژول ۲ و ۴ قابل‌استفاده باشد (یک «نرخ فعال» مشترک در state).
