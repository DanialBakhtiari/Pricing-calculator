# Rule — استانداردهای کدنویسی

**اعمال:** همیشه، روی هر فایل.

## TypeScript
- `strict: true`. هیچ `any` ضمنی. برای داده‌ی خارجی از `unknown` + zod parse.
- نوع‌ها صریح روی مرز ماژول‌ها (props، خروجی توابع core).
- از `as const` برای جدول‌های داده (CM_LEVELS و …) استفاده کن.

## ساختار
- یک کامپوننت = یک مسئولیت. اگر از ~۱۵۰ خط گذشت، بشکن.
- منطق محاسباتی **فقط** در `src/lib/pricing`. کامپوننت فرمول ننویسد.
- تابع خالص را خالص نگه دار: بدون I/O، بدون `Date.now()` داخلش (تزریق کن).
- نام‌ها معنادار و انگلیسی؛ توابع فعل، متغیرها اسم.

## React
- تابعی + هوک‌ها. بدون کلاس‌کامپوننت.
- `useMemo` فقط برای محاسبات گران یا مرجع پایدار؛ بهینه‌سازی زودرس نکن.
- side-effect در `useEffect` با وابستگی درست؛ از افکت برای محاسبه‌ی مشتق‌شدنی استفاده نکن.
- فرم‌ها: react-hook-form + zodResolver؛ ورودی کنترل‌شده فقط وقتی لازم است.

## خطا و اعتبارسنجی
- هر تابع core ورودی را با zod اعتبارسنجی و خطای خواناروی پرتاب/برگرداند.
- مرز UI: خطاها را بگیر و به پیام فارسی از `content/fa` تبدیل کن.

## کیفیت
- بدون کد مرده، بدون `console.log` در نهایی، بدون TODO بدون issue.
- هر رفتار غیربدیهی یک تست دارد. هر باگِ رفع‌شده یک تست رگرسیون می‌گیرد.
- کامیت‌ها کوچک و Conventional Commits.

## وابستگی‌ها
- اضافه‌کردن هر پکیج باید در `docs/DECISIONS.md` توجیه شود (چرا، اندازه، جایگزین).
- ترجیح: راه‌حل بومی/سبک بر کتابخانه‌ی سنگین.
