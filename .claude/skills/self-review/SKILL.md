# Skill — خود-بازبینی (Self-Review)

قبل از اینکه هر واحد کار را «تمام» اعلام کنی، نقش **reviewer سینیور** را بگیر و این چک‌لیست را اجرا کن. هر «نه» = برگرد و اصلاح کن.

## درستی
- [ ] خروجی با Test Vectorهای Spec می‌خواند؟ (اگر منطق محاسباتی است)
- [ ] حالت‌های لبه: صفر، عدد خیلی بزرگ، ورودی خالی، اعشار، ارقام فارسی؟
- [ ] خطاها مدیریت و به پیام فارسی تبدیل شده‌اند؟

## کیفیت
- [ ] `typecheck` + `lint` + `test` + `build` همه سبز؟
- [ ] فرمول در UI تکرار نشده؟ منطق در core است؟
- [ ] کامپوننت کوچک و تک‌مسئولیت؟ بدون کد مرده/console؟

## UX/RTL/A11y
- [ ] هر فیلد InfoTooltip دارد؟ متن از content/fa؟
- [ ] RTL سالم (بدون left/right فیزیکی)؟ موبایل ۳۶۰px؟
- [ ] کیبورد/فوکوس/کنتراست/aria روی tooltip و chart؟
- [ ] حالت‌های empty/loading/error/success پیاده شده؟

## محصول
- [ ] معیار پذیرشِ همان فاز در docs/06-PHASES.md برآورده شده؟
- [ ] ریسک/بدهی فنی باقی‌مانده را یادداشت کردی؟

## گزارش
در پایان یک خلاصه‌ی کوتاه بده: «چه ساختم / چه تستی سبز شد / چه چیزی باز ماند». اگر بعد از ۳ دور حلقه هنوز معیاری رد است، به‌جای ادامه، مسئله را شفاف گزارش کن.
